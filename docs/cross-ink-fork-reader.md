# Reader improvements replayed onto CrossInk

This branch starts from CrossInk development `4a397886`, retaining its reader,
FreeInkUI drawer, settings, themes and native pagination engine. The reader
changes below adapt personal Witch Hunt improvements to those interfaces.

## Saved data

New EPUB/TXT/XTC cache directories are `crossink_epub_<FNV64>`,
`crossink_txt_<std::hash>` and `crossink_xtc_<std::hash>` under `/.crosspoint`.
Cache cleanup, library completion checks and home progress lookups use the new
directories. They do not rename or delete Witch Hunt's `epub_`, `txt_` or `xtc_`
directories. Existing books, fonts and dictionaries keep their paths.

An EPUB with no new progress slot imports the old position read-only. Witch's
seven-byte prefix contains a percent byte at offset six; that byte is never
treated as CrossInk's visible-text offset. Optional paragraph and `SRC1` source
anchors are decoded explicitly. The original record remains untouched; normal
subsequent saves use CrossInk's CRC-protected alternating progress slots. If
either new slot exists but both are corrupt, no older Witch progress replaces
it silently. TXT/XTC progress uses compatible legacy prefixes read-only until
the first save in its new cache. A corrupt existing new record is authoritative.

Recent books use `crossink-recent.json`. First import reads the old JSON (or
backup-only JSON) without modifying it, retaining original Witch preference
fields on disk. CrossInk's own per-book settings remain independent; old binary
layout caches and per-book preference payloads are not reinterpreted.

Witch's per-cache `bookmarks.bin` and global
`global_bookmarks.bin` / `reading-stats.bin` / `reading-stats.json` are not
overwritten. Native bookmarks use a separate `bookmarks/<type_hash>.bin` store;
native statistics use `global_stats[_device].bin`, `synced_stats` and the new
per-book caches. Native dictionary history is in those new caches; native
clippings have no corresponding Witch store. Incompatible
page-only bookmarks and aggregate statistics are preserved for rollback rather
than guessed into another format.

## Reader behavior

- Full-book phrase search is available in the native reader drawer's More tab.
  It folds Unicode case (including expansions), whitespace and ignorable marks,
  joins inline text, separates blocks and skips head/script/style/SVG plus
  explicitly hidden/inline `display:none` content. External CSS visibility is
  not evaluated by the search scanner. Chapter text, search, body-font discovery
  and preview location share bounded SAX HTML repair with original byte mappings;
  package XML remains strict.
- Search streams stored or compressed ZIP entries using CrossInk's existing
  incremental reader. Scratch size is fixed, queries are capped at 128 bytes,
  snippets at 240 bytes and results at 10,000. Results live in an exclusively
  created, session-owned temporary file. Failed or unstarted sessions cannot
  overwrite or remove another session's results. Back cancels and removes only
  the active session's file. Repaints are throttled while scanning.
- Selecting a search result rebuilds the destination section with a raw XHTML
  source target. Cached page source ranges are used only when unambiguous;
  otherwise a parser probe resolves the original word/character. Visible text,
  paragraph and proportional positions remain fallbacks for older records.
- Go back is a one-shot footer and More-tab action after chapter, percentage, stable-page,
  bookmark, clipping, search or internal-link jumps. It survives five ordinary
  page turns. Footnote returns and sleep-resume history retain original source
  positions plus native text offsets and page counts for compatible fallback.
- A hold for dictionary lookup must have begun on the same fully rendered page
  and orientation. A contact spanning a page change cannot look up a word from
  the new page. CrossInk's dictionary selection UI remains intact.
- Ignore publisher page margins appears in native Layout/settings and per-book
  overrides. It removes margins/padding from `html` and `body` only; nested block
  spacing, wrapper divs and paragraph indentation remain publisher controlled.
  Extra paragraph spacing defaults to off for newly initialized settings.
- Publisher `text-transform` supports inherited Unicode uppercase/lowercase and
  explicit resets. Expansion and NFC composition retain original text coordinates
  through CJK tokenization, hyphen insertion and partial page layout, so search,
  saved positions and reflow use the same source location. Default Unicode 15.1
  case mappings are generated by `scripts/generate_unicode_case.py`; contextual
  Greek final sigma and language-specific Turkic/Lithuanian tailoring are not
  implemented. Publisher tracking inherits computed spacing, supports `normal`,
  `inherit`, px/pt/em/rem and is bounded to ±32 display pixels.

## Formats

Section version 109 / partial marker `0xDE` includes 64-bit publisher-face masks,
exact typography, gray/nested boxes, table images and a 14-byte source summary per
page. The summary stores the original XHTML word byte offset, original character
offset and the page's source range. Source maps remain transient per-word layout
data. Native layouts rebuild automatically; progress and books remain intact.
CSS cache version 25 stores a 149-byte fixed style payload plus bounded ordered
font catalogs and document-local overlays. See `file-formats.md` and
`css-parity-cache.md` for the layouts and retry rules.

Per-book reader-settings version 14 appends the margin override after publisher
fonts; older version 13 remains readable, with its original override-bit mapping.

`links.bin` starts with bytes `L`, `R`, `3`, depth. Each 16-byte entry stores
little-endian spine `u16`, page `u16`, page count `u16`, visible-text offset `u32`,
raw source offset `u32` and character offset `u16`. Depth stays capped at three;
LR2 ten-byte entries and native four-byte page-only entries remain readable.
The new cache namespace keeps Witch's `linkstack.bin` untouched. Progress slots
retain their existing 20-byte CRC record when no source is known, and use an
optional 26-byte source extension when one is available.

## Equivalents and intentional adaptations

Native CrossInk already has publisher font modes, dictionary font settings,
configurable word spacing, selectable TTFs, embedded family handling, small caps,
drop caps, tables, borders, whitespace modes and status-bar tap controls. The
later parity work adapts publisher family fallback, fractional sizing and
bitmap rendering through bounded native font providers; see
[font behavior](cross-ink-fork-fonts.md). Image warming similarly uses native
cache-only decoding and the render task; see [image behavior](cross-ink-fork-images.md).
The reverted personal dark-mode experiment is not replayed. Pluto sync,
single-pass text AA and screen-media handling remain separate integrations.

## Validation

Focused production tests cover progress decoding/precedence, raw UTF-8/entity
source mapping, native section persistence, margin isolation, dictionary hold
identity, precise link returns and one-shot expiration. Search tests exercise
Unicode matching, bounded stored/deflated ZIP scanning, result limits, concurrent
temporary ownership, cancellation, malformed/missing sections and SD write/read/
close failures. Typography checks cover CSS cache round trips, inherited computed
tracking, full Unicode expansion/composition, drop-cap fallback, character and
hyphen splits, CJK tokenization, partial-line consumption and raw source targets.
The image-framebuffer extraction regression runs under ASan/UBSan.
These host checks do not establish physical touch accuracy or e-ink appearance.
