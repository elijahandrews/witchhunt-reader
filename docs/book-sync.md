# Home-library book sync

**File Transfer → Pluto local book sync** adds missing EPUBs from a compatible HTTPS helper.
The reader joins ordinary Wi-Fi and resolves the configured hostname using that
network's DNS. It does not implement SMB or require Tailscale.

Configure the reader privately over USB with `/.crosspoint/book-sync.json`:

```json
{"url":"https://books.example.test:8444","token":"<64 lowercase hex characters generated by the helper>"}
```

Put the helper's trusted CA certificate at `/.crosspoint/book-sync-ca.pem`.
Neither the JSON nor certificate is compiled into firmware. The token is a
read-only service credential, distinct from SMB credentials. The card stores it
in plaintext; keep it out of repositories and public backups. Use a hostname
that resolves on the reader's home network, and issue the server certificate for
that name. The reader requires valid certificate dates and may need NTP after
boot. Its global skip-HTTPS-validation setting does not apply to this connection.
Redirects and plaintext HTTP are refused.

Sync scans existing nonhidden EPUBs throughout the SD card. It first filters by
the byte lengths in the current helper inventory, avoiding content reads for books
that cannot match. Candidates still receive a complete SHA-256 check; no filename
or cached timestamp is trusted as proof of matching content. Identical files are
skipped even if copied by USB with different filenames. Existing book paths,
reading progress, annotations and settings are preserved. Different content or
metadata produces a different hash and can result in a separate copy. Existing
sync destinations are never replaced: differences are counted as conflicts.
There is no remote deletion or progress synchronization.

New books go directly to `/Books`. Existing copies anywhere on the card, including
the former `/Books/Sync` directory, are still recognized and skipped. Sync does
not automatically relocate existing books. Each download is staged privately, then checked for
exact byte length, SHA-256 and ZIP signature before publication. During checking,
the screen shows books examined and MiB read. Tap **Cancel** or press Back to stop;
input is serviced between 8 KiB reads, including while checking local books.
Cancellation waits for any current SD read or display operation to return;
completed books remain and incomplete data is removed. Retry reruns the inventory
and skips completed content. Leaving the activity restarts the reader, like its
other memory-intensive network activities.

## Helper protocol v1

All requests use HTTP Basic authentication with username `reader` and the private
hex token as password. Only a configured HTTPS origin is accepted. The helper
must expose these two endpoints without redirects:

- `GET /v1/manifest`: complete ASCII inventory, bounded to 3 MiB.
- `GET /v1/files/<path-id>/<content-sha256>`: EPUB bytes matching that inventory.

The manifest has newline-terminated lines:

```text
WITCHSYNC1
<64 lowercase content hash><TAB><decimal byte length><TAB><filename>
END<TAB><record count>
```

A filename is a 1–60-character ASCII title containing letters, digits, spaces,
underscores or hyphens, followed by `~`, a 64-character lowercase SHA-256 of the
UTF-8 source-relative path, and `.epub`. Records are strictly sorted by filename;
duplicates, path separators and malformed fields are rejected. Limits are 10,000
books, 512 MiB per book, and 256-byte line buffers. The footer count and complete
inventory are checked before any book is fetched. New files with identical
contents in the same inventory are deduplicated too.

The helper should provide Content-Length and support explicit byte ranges for
memory-constrained TLS clients. It must confine reads to its library, reject
symlink traversal, and fail inventory requests when a scan cannot be completed.
Inventory parsing and local hash indexing use bounded memory and temporary SD
files under `/.crosspoint/book-sync/`; no full library is held in firmware RAM.
