# Runtime outline faces

`OutlineFontFace` opens borrowed memory or a random-access stream and exposes the callback contract in `EpdOutlineFontCallbacks.h`. One registration fixes its logical display-pixel em, weight, italic and hinting. Legacy metrics, advances and bitmaps retain the density-2 em; renderer base scale is 0.5. Advances and kerning use 1/16 raster pixel, matching the existing density-2 bitmap path. The optional final-size raster callback uses this same scale to produce display-pixel bounds and coverage without changing layout advances. Glyph IDs are distinct from Unicode, so authored small-cap and ligature glyphs do not require private Unicode mappings.

The optical-size axis uses typographic points: by default `logicalPx * 72 / 150`, independently of the density-2 raster. A positive `Options.opticalPoints` explicitly overrides this. Supported axes are clamped to their authored ranges; unknown axes retain their defaults. The slant axis is not guessed from a boolean italic request. Fonts without an optical axis keep their authored outlines. The weight and italic axes are set before metrics or rasterization. The default hinting is FreeType light hinting (FreeType selects native CFF hinting when supported); Native and unhinted options are available.

The build must register the matching PSHinter module alongside CFF. Without it, the CFF driver can scale hinted outlines twice while reporting correct advances; the host suite checks CFF raster bounds against independent design-unit geometry.

Each face has an explicit allocation budget (default 1 MiB) and a combined GSUB/GPOS/GDEF table budget (512 KiB). Missing tables are valid; present tables that cannot be retained reject the face, rather than silently dropping their layout. PSRAM holds the implementation, metrics cache, FreeType arena, layout tables and packed raster. Individual FreeType allocations may fall back to at most 2 KiB cumulative internal memory per face. Devices without PSRAM reject runtime outline faces. Optional paired `claimMemory`/`releaseMemory` callbacks enforce a shared payload budget; denied allocations and malloc failures report `memoryFailure`, and failed reservations roll back. Initialization verifies every required FreeType module and rejects any allocation-failed open. The EPUB manager uses these callbacks for a 3 MiB aggregate payload budget and evicts older family sizes while protecting the two most recently resolved registrations. Returned bitmap memory is borrowed until the next bitmap request or face destruction. Empty glyphs have zero bytes and a null bitmap.

Logical em values from 1 to 120 display pixels are accepted subject to per-font bounds: raster line advance must fit the existing uint8 field, glyph advance must fit uint16 fixed-point, and packed glyph raster size must fit the existing 65535-byte limit. Oversized or malformed faces/glyphs fail cleanly.

Supported OpenType layout is deliberately bounded: Latin/DFLT default language systems, `smcp`/`c2sc` single substitutions (including extension lookups), SDK Latin ligatures of two or three glyphs, and horizontal pair kerning. Caps return zero when the requested feature supplies no supported alternate, allowing the reader's explicit synthetic fallback. Pair kerning includes GPOS `XAdvance` VariationIndex deltas from the GDEF ItemVariationStore. Complex-script shaping, contextual substitutions, placement/mark attachment, pixel-size Device adjustments and GSUB/GPOS FeatureVariations substitutions remain outside this bounded reader.

`SdkGpos.cpp`, `SdkGsub.cpp` and their headers derive from FreeInk SDK commit `c6e1d2bd36e31bb9f1abaf42706215e4bf004cb7`; the local pair reader adds authored lookup accumulation and instance-specific variation deltas. Its MIT license is included in `LICENSE.SDK`. The independent caps parser preserves authored lookup order and rejects unsupported selected lookups. Pinned FreeType source/license provenance is documented in `../FreeType/README.md`.

Host checks are under `../../test/outline_font`; they compile this production backend and the checked-in FreeType translation units directly, without a system FreeType dependency.

## Fractional outline rasterization

`raster(gid, scale, phase, out)` rasterizes at `logicalPx * 2 * scale` display pixels. `phase` is a signed offset from the integer pen, from -8 to 7 in sixteenths of a display pixel. The default `FinalSize` policy hints at that final size with LIGHT hinting, translates the actual outline, and quantizes FreeType's 8-bit grayscale coverage once to the panel's four shades. It does not filter a previously quantized bitmap. Callers consume the returned bounds and pixels directly, without scaling or shifting them a second time. Linear advances and pair kerning keep the existing authored spacing.

For controlled host comparisons, `RasterPolicy::Oversample2x` hints/renders at twice the requested display em and integrates the full 8-bit coverage of each 2×2 cell before the one final quantization. `LegacyBitmap` disables the callback and requests the existing bitmap fallback. `phaseSteps` accepts 4, 8 (default), or 16. Eight phases limit horizontal origin error to 1/16 display pixel. Negative origins share cached positive phases with an integer bearing adjustment; empty glyphs retain neutral bounds. Policy and hinting are fixed for the face lifetime.

A separate FreeType size object preserves the legacy hinting state. Every uncached request restores the original size and clears its transform, including failure exits; the shared glyph slot is marked dirty so a subsequent legacy bitmap cannot reuse the new raster by mistake. Legacy bitmap, metrics and kerning calls leave the final raster's borrowed pixels intact. The raster pointer is guaranteed only until another raster request or face destruction.

The phase cache has 512 entries and a 32 KiB packed-pixel arena (about 48 KiB payload on 32-bit devices), allocated lazily once from PSRAM and charged to the existing face/shared memory budget. This covers roughly 60 common glyphs at eight phases while avoiding per-glyph heap allocation. Either limit evicts the entire cache generation; there is no unbounded growth or additional framebuffer. Allocation, glyph-size or unsupported-input failures request the existing bitmap fallback. Hardware timing and perceptual quality still require a physical comparison; host bitmaps alone cannot calibrate e-ink shade response.

`Options.applyVariations=false` keeps the font's default variation instance without changing axes. `Options.loadLayoutTables=false` skips retained GSUB/GPOS/GDEF copies; the native SD adapter uses both options and retains its existing default-instance layout reader. Both default true for embedded EPUB faces. The separate raster callback does not add complex-script shaping.

The local OpenType readers use the `witchoutline` namespace to coexist with upstream native TTF readers. Native SD TTF, embedded outlines and v6 converted fonts use authored `smcp`/`c2sc` glyphs where available, with a per-character synthetic fallback for missing or unsupported substitutions. Native caps reuse the bounded, allocation-free GSUB reader and carry validated alternate glyph IDs through the existing metrics, bitmap/raster and kerning paths; alternate pairs bypass the Unicode-only pair cache to avoid key collisions. No extra retained caps table or cache is allocated.

## Variable pair kerning

Embedded variable faces retain the actual normalized 16.16 coordinates returned by `FT_Get_Var_Blend_Coordinates` after axes are selected, including `avar` mapping. GPOS PairPos formats 1 and 2, including extension lookups, use those coordinates to interpolate the first value record's `XAdvance` adjustment. A device-only variation record is supported. Format 1 offsets are relative to the PairSet; format 2 offsets are relative to PairPos. The combined delta is rounded once before scaling with the same face size as its advances. Wide intermediates and final saturation prevent malformed deltas from wrapping the fixed-point result.

Variation interpolation allocates nothing per pair. The borrowed GDEF table shares the existing table and face budgets; the face retains four bytes per axis, capped at 64 axes. Region/axis work shares the existing 4096-step pair-lookup budget. Static faces and the native layout-disabled path allocate no variation context. Malformed offsets, counts and unavailable variation data contribute no delta; budget exhaustion rejects the whole pair result. A present table that cannot be retained rejects the face, preserving the existing fallback policy.

The parser follows the [OpenType ItemVariationStore format](https://learn.microsoft.com/en-us/typography/opentype/spec/otvarcommonformats#item-variation-store) and [GPOS ValueRecord rules](https://learn.microsoft.com/en-us/typography/opentype/spec/gpos#value-record); instance coordinates come from [FreeType's blend-coordinate API](https://freetype.org/freetype2/docs/reference/ft2-multiple_masters.html#ft_get_var_blend_coordinates). Native SD variable fonts continue to use their default instance; this change applies variable layout to embedded runtime faces.
