# Runtime outline faces

`OutlineFontFace` opens borrowed memory or a random-access stream and exposes the callback contract in `EpdOutlineFontCallbacks.h`. One registration fixes its logical display-pixel em, weight, italic and hinting. The FreeType face renders at twice the logical em; renderer base scale is 0.5. Advances and kerning use 1/16 raster pixel, matching the existing density-2 bitmap path. Glyph IDs are distinct from Unicode, so authored small-cap and ligature glyphs do not require private Unicode mappings.

The optical-size axis uses typographic points: by default `logicalPx * 72 / 150`, independently of the density-2 raster. A positive `Options.opticalPoints` explicitly overrides this. Supported axes are clamped to their authored ranges; unknown axes retain their defaults. The slant axis is not guessed from a boolean italic request. Fonts without an optical axis keep their authored outlines. The weight and italic axes are set before metrics or rasterization. The default hinting is FreeType light hinting (FreeType selects native CFF hinting when supported); Native and unhinted options are available.

The build must register the matching PSHinter module alongside CFF. Without it, the CFF driver can scale hinted outlines twice while reporting correct advances; the host suite checks CFF raster bounds against independent design-unit geometry.

Each face has an explicit allocation budget (default 1 MiB) and a combined GSUB/GPOS table budget (512 KiB). Missing tables are valid; present tables that cannot be retained reject the face, rather than silently dropping their layout. PSRAM holds the implementation, metrics cache, FreeType arena, layout tables and packed raster. Individual FreeType allocations may fall back to at most 2 KiB cumulative internal memory per face. Devices without PSRAM reject runtime outline faces. Optional paired `claimMemory`/`releaseMemory` callbacks enforce a shared payload budget; denied allocations and malloc failures report `memoryFailure`, and failed reservations roll back. Initialization verifies every required FreeType module and rejects any allocation-failed open. The EPUB manager uses these callbacks for a 3 MiB aggregate payload budget and evicts older family sizes while protecting the two most recently resolved registrations. Returned bitmap memory is borrowed until the next bitmap request or face destruction. Empty glyphs have zero bytes and a null bitmap.

Logical em values from 1 to 120 display pixels are accepted subject to per-font bounds: raster line advance must fit the existing uint8 field, glyph advance must fit uint16 fixed-point, and packed glyph raster size must fit the existing 65535-byte limit. Oversized or malformed faces/glyphs fail cleanly.

Supported OpenType layout is deliberately bounded: Latin/DFLT default language systems, `smcp`/`c2sc` single substitutions (including extension lookups), SDK Latin ligatures of two or three glyphs, and horizontal pair kerning. Caps return zero when the requested feature supplies no supported alternate, allowing the reader's explicit synthetic fallback. Complex-script shaping, contextual substitutions, placement/mark attachment and variable GPOS/GSUB feature deltas are not implemented. Optical-axis outline/advance changes are applied; this does not promise complete shaping of variable-font layout tables.

`SdkGpos.cpp`, `SdkGsub.cpp` and their headers derive from FreeInk SDK commit `c6e1d2bd36e31bb9f1abaf42706215e4bf004cb7`; the local pair reader adds authored lookup accumulation. Its MIT license is included in `LICENSE.SDK`. The independent caps parser preserves authored lookup order and rejects unsupported selected lookups. Pinned FreeType source/license provenance is documented in `../FreeType/README.md`.

Host checks are under `../../test/outline_font`; they compile this production backend and the checked-in FreeType translation units directly, without a system FreeType dependency.
